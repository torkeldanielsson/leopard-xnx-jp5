# Leopard Xavier NX GMSL2 box on JetPack 5

Camera support for the **Leopard Imaging LI-XNX-BOX-GMSL2** on **Jetson Linux
R35.6.5** (JetPack 5, kernel 5.10). The box has a Xavier NX eMMC module and six
Sony IMX185 cameras on three MAX9296A deserializers, two MAX9295 serializers
each. It shipped with L4T 32.4.3 (JetPack 4.4).

This is an independent project, not a Leopard Imaging or NVIDIA release.

## Status

All six cameras start automatically at boot and capture 1920×1080 at 30 fps,
through raw V4L2 and through Argus (`nvarguscamerasrc`). CUDA 11.4 and cuDNN
8.6 from JetPack 5 run, and the TensorRT library loads
([`evidence/jp5-runtime-check.txt`](evidence/jp5-runtime-check.txt)).

The deserializers keep their registers through a reboot, and Leopard's link
setup leaves them in a mode where their I2C fails once the cameras restart.
The bridge driver selects a single link at shutdown and again at startup,
fully resets a deserializer if that fails, and then runs the setup. See
[porting notes](docs/porting-notes.md#startup-after-a-reboot).

Tested on one box. After each reboot and the cold start below, all six
cameras passed the acceptance test: 6 × 90 raw frames one camera at a time,
6 × 300 raw frames all at once, and 6 × 120 Argus frames. Logs:
[`evidence/six-camera-tests.log`](evidence/six-camera-tests.log).

- Three normal reboots: every pair started on the first attempt.
- Five hard reboots that skip the shutdown step: link A selection failed on
  seven of the fifteen pair starts, and the full reset brought each back
  after 1 to 24 resets. Each of those pairs started 7 to 22 seconds later.
- A cold start after power had been disconnected, with the previous version
  of the driver, which allowed fewer resets: every pair started on the first
  attempt.
- A test build that fails pair 0 on purpose: pairs 1 and 2 still started, and
  their four cameras captured.
- Switching camera power off and on three times: pair 1, with both links
  enabled, stopped answering reliably each time, while pairs 0 and 2, on link
  A, started on the first attempt afterwards.

Only the 1080p30 mode the box shipped with is supported.

## What you need

- The box, still running its original 32.4.3 image. **Before upgrading, copy
  two files off it.** The upgrade replaces them:
  ```sh
  sudo dtc -I fs -O dtb -o live-r32.4.3.dtb /sys/firmware/devicetree/base
  cp /var/nvidia/nvcam/settings/camera_overrides.isp .
  ```
  The DTB on disk does not describe the cameras. Use the device tree exported
  from the running system. The ISP file is Leopard's camera tuning; it is not
  included here.
- An x86 Linux build host with NVIDIA's R32.4.3, R32.7.3 and R35.6.5 BSPs.
- USB storage for the update payload. Bring-up used the virtual USB drive of a
  GL.iNet Comet KVM.

Then follow [build and install](docs/build.md). It covers the kernel, device
tree and the over-the-air upgrade 32.4.3 → 32.7.3 → 35.6.5.

## Try it without hardware

```sh
make -C driver
./driver/leopard-gmsl init 30   # print the link setup sequence for the first pair
python3 test-evidence.py        # check the register tables against recorded I2C traffic
python3 test-packaging.py       # check the helper scripts (needs python3-requests)
```

## Testing on the box

Install `v4l-utils`, `python3-gi`, GStreamer and NVIDIA's Argus runtime. Stop
other camera clients, copy `test-cameras.sh` and `test-argus.py` to one
directory on the Jetson and run:

```sh
sudo bash test-cameras.sh capture-output
```

The script stops the Argus daemon during raw capture and restarts it afterwards.
`test-argus.py` counts real buffers and requires increasing timestamps. Output
includes raw frames and system logs.

To test restarts without anyone at the box, `leopard-pmic-reset` resets the
Xavier NX module through its PMIC, and the module starts again by itself. Set
your module's serial number in the script, install it in
`/usr/lib/systemd/system-shutdown/`, and arm it for the next reboot by writing
the serial number to `/run/leopard-pmic-reset-armed` (owned by root, mode
0600). `leopard-pmic-reset --check` only reads the PMIC registers. The reset
runs before the kernel's shutdown step, so unload `leopard_imx185` and
`leopard_gmsl` first; unloading selects link A. It does not cut power to the
carrier board, so it does not reset the deserializers.

## Layout

| Path | Contents |
| --- | --- |
| `driver/leopard_gmsl.c` | Bridge driver: shared camera power, link selection, link setup, stream gates |
| `driver/leopard_imx185.c` | NVIDIA's R35.6.5 IMX185 driver adapted to this box by `prepare-sensor.py` |
| `driver/leopard-gmsl.c` | Userspace tool that prints, applies or checks the link setup |
| `driver/profile.json` | Register tables recovered from the original kernel |
| `driver/leopard_tables.h`, `driver/leopard_imx185_mode_tbls.h` | The tables as C, generated by `extract-profile.py` and `prepare-sensor.py` |
| `driver/leopard_gmsl.h`, `driver/Makefile` | Interface between the two modules; build for the modules and the tool |
| `patches/` | Two fixes to NVIDIA's PCA954x I2C mux driver |
| `config/` | Kernel configuration of the tested build |
| `port-device-tree.py` | Moves the camera topology from the original device tree into an R35 one |
| `install-r35-camera.sh`, `setup-rootfs.sh`, `make-ota-media.sh`, `comet-media.py` | Install into the BSP, prepare the rootfs, build and attach update media |
| `test-cameras.sh`, `test-argus.py` | Hardware acceptance test |
| `leopard-pmic-reset` | Remote module reset for restart tests |
| `test-evidence.py`, `test-packaging.py` | Offline tests: register tables against recorded traffic, helper scripts |
| `capture-baseline.sh`, `LeopardFunctions.java` (Ghidra script), `extract-profile.py`, `validate-trace.py` | Tools used to recover the configuration from the original system |
| `docs/` | [Build and install](docs/build.md), [porting notes](docs/porting-notes.md) |
| `evidence/` | Recorded I2C traffic and acceptance results, used by `test-evidence.py` |
